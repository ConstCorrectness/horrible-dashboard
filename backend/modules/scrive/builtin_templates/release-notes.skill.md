Release notes are read by people deciding whether upgrading is safe.

- Write for users, not contributors: what changes for them, not how it was built.
- Breaking changes are never buried: each gets a before/after code snippet.
- Link every item to its issue or PR; take facts (versions, names, flags) only from
  what the user gave you or the sources you read — never invent a changelog entry.
- Prefer a code block over a sentence whenever an API changed.
