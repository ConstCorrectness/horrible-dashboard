## Design Specificity Verdict

Split verdict: the design system is exceptionally product-specific; the application is not, because the system is barely installed.

Executed well: datalist.css (identity/telemetry split as a structural rule; verdict rail as ::before inset to top:9px because the clip-path would slice a border-left's corner). ActivityRail.tsx's four-state glyph (active/docked/center/closed).

Reach: clip-path motif 3 real uses. ResourceCard 1. var(--control-h) 4 (verified). Button 74 vs 701 raw button elements (9.5%). EmptyState 7 vs 75+ ad-hoc strings.

Counterweight: 1,122 hardcoded hex literals in .tsx — GitHub Primer dark (#8b949e, #c9d1d9, #30363d, #161b22) and Tailwind defaults (#38bdf8, #f87171, #4ade80). Six files carry 435. ~20 font sizes where the scale defines six. 12 gap values, none landing on the px scale. 357 native emoji as in-pane glyphs (excluding sanctioned manifest icon: fields). 1,960 inline style objects across 139 files — DESIGN.md's stated debt of ~1,987 is untouched.

Missed opportunity: the frame's roles (document/tool/widget) are the most distinctive idea in the product and have no visual grammar. frame.css is 1,368 lines and never expresses role as a visual property.

## Priority Issues

### [P0] The tier-1 front door is unreachable on a clean install

HomeView renders from exactly one place — desktop/backdrops/Splash.tsx:61 — and DEFAULT_BACKDROP = 'aurora' (layout/types.ts:201). Verified at source. Avatar, ask bar, connector tiles and SetupCard never appear by default. PRODUCT.md's first positioning claim and the two-tier design are both unshipped to anyone taking defaults. The choice is buried on a wizard step titled "Pick a look", weighted like a decorative wallpaper.

Fix: DEFAULT_BACKDROP = 'splash'; split the two interactive:true backdrops into their own step ("How should the desktop start?") with live preview and a selected state.

Command: /impeccable onboard

### [P1] Agent-not-ready is the central failure and reports nothing

ChatWidget.tsx:245 computes ready = status.configured && status.reachable; line 649 renders both failures as "Agent not ready — / for commands" in the input placeholder. configured:false is a two-click setup task; reachable:false is a dead server. The component holds both booleans and discards the distinction — the exact inversion of the product's own three-state degrade-loudly principle.

Fix: warn chip banner above the input with cause + action per state; three example prompts in the empty transcript.

Command: /impeccable clarify

### [P2] 1,122 hardcoded hexes defeat the theme switcher in whole modules

Live-verified: under data-theme="daylight", Trajectories rendered fully dark while Settings rendered light in the same screenshot. The token guard catches undefined var() names, not a literal in an inline style object.

Fix: extend design-tokens.test.ts to fail on a hex-literal regex in .tsx/.ts, allowlisting canvas/WebGL sites with a required comment. Clear six files (RoomsPanel 187, TownMapCanvas 66, DeveloperConsole 49, EvalsHub 46, RunDetailsModal 45, TrajectoriesHub 42) = 39% of the total.

Command: /impeccable harden

### [P3] The Start menu is the primary IA and it's an unsorted directory listing

51 openers under 38 headers, 22 with exactly one item; alphabetical by module id; no recents. 14 desktops incl. two identical rows, no active marker. Settings nav shows "Hardware" and "Updates" twice — verified: hardware/index.tsx declares both a module title and a settings-section title of 'Hardware'.

Fix: collapse single-item groups; add a Recent band from pane-open history already tracked in layout/pane-lifetime; mark the active desktop with the data-kind rail; reject duplicate workspace names; disambiguate section titles colliding with module titles.

Command: /impeccable layout

### [P4] The One Height Rule is specified but not installed

var(--control-h) at 4 sites, all inside primitives.css/resourcecard.css. controls.css never mentions it and sets height:26px (line 113) and 20px (line 137). Consequence caught independently: a select measuring 413px inside a 348px Settings pane, sizing to its longest option with min-width:auto.

Fix: min-height: var(--control-h) on the input/select/textarea/button baseline in controls.css; delete the 26/20px literals; min-width:0 on the select. Also minmax(240px appears zero times; two minmax(420px grids break the 320px survivability bar.

Command: /impeccable polish

## Persona Red Flags

Jordan (first-timer): boots to empty wallpaper + taskbar. No product identity in the shell. Start = 74 targets; "Agent stub" sits under "Agent" with no indication which is real. Agent pane input reads "Agent not ready" with the send button at full strength beside it. SetupCard/OnboardingCard/connector tiles never rendered. Dead end; does not recover.

Alex (power user): M-x, spotlight, chord hints genuinely good. Settings nav = 37 items in registration order with two duplicate label pairs. All 144 settings render at once (55KB DOM); nav is an anchor list, not a filter. hardware.accelerator offers six options without showing what the probe found, though the backend computes Profile.certain plus a reason string. outline:none x20 vs :focus-visible x17.

Sam (plugin author): Marketplace empty state hands over a raw env-var name to retype — no example path, no copy button, no SDK docs link. "Plugins are trusted code" warning uses .dashboard-hint, the same class as filler copy; no confirm on install. The Marketplace does not use the design system it advertises (hand-built .mk-list/.mk-item, no DataList/ResourceCard/notch/rail). Reload banner calls window.location.reload() with no warning in an app whose panes own PTYs and sockets.

## Minor Observations

- .settings-title is the only pane header using Instrument Serif (28px); DESIGN.md reserves it for games ceremony type.
- 11 spinner implementations; "loading" spelled four ways.
- Taskbar breaks at 800px: M-x wraps, date wraps. No overflow strategy on the status zone.
- 76 aria-labels across 701 raw buttons; ~24 icon-only buttons carry title alone.
- --text-faint on --bg is 2.91:1 — not fine for .dashboard-hint, which carries empty-state copy and the Marketplace security warning.
- Chevron/SendGlyph in HomeView.tsx are hand-drawn SVGs with a comment on why; makes the 357 emoji elsewhere look like an unenforced rule.
- Both agents flagged side-tab (border-left: 3px) — check against the documented rule that a rail on a clipped container must be an inset pseudo-element.

## Questions to Consider

1. If HomeView has only ever rendered under one non-default wallpaper, has anyone used the product as a first-time user sees it? What would a "front door reachable from a clean install" test look like, and would it pass?
2. The frame's roles carry zero visual weight. What if a role were a token?
3. DESIGN.md names 1,987 inline styles as debt; the count is unchanged at 1,960. Specification or wish?
4. ResourceCard has its own CSS file and one caller. What's the actual barrier to adoption?
5. What would it cost to say one sentence about the credential architecture where the user types an API key?
