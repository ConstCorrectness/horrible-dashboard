# Regions

Regions are toggleable, resizable **strips inside a pane's area** — Blender's
N/T-panel idea applied to every view. They replaced **panel groups**: instead of
a hand-rolled mini-dock rendered inside one pane (the old `PaneGroupShell`),
regions are **engine-native and persisted** — part of the pane's state in the
layout store, saved with the workspace, restored exactly as left.

## Concept

A view declares the region views it hosts in its manifest (`regions` on a
`PanelDecl`/`WidgetDecl`):

```ts
{
  id: 'editor.buffer',
  role: 'document',
  regions: [
    { id: 'code.outline',       label: 'Outline',       icon: '≡', key: 'o', position: 'right' },
    { id: 'code.search',        label: 'Symbol Search', icon: '⌕', key: 's', position: 'right' },
    { id: 'git.provenance',     label: 'Provenance',    icon: '⎇', key: 'g', position: 'right' },
    { id: 'editor.recentNotes', label: 'Recent notes',  icon: '🗒', key: 'r', position: 'left'  },
  ],
}
```

- Each **position** (`left`/`right`/`bottom`) is one strip; multiple views at
  the same position **stack as tabs** within it.
- A region view is any registered panel/widget id — cross-module is fine (the
  editor hosts views from the `code` and `git` modules).
- Region state is **per pane instance**: every editor buffer keeps its own
  strip sizes, open flags, and active views, persisted with the layout.
- A strip can also **collapse** to a thin rail (Blender's tucked toolbar)
  without forgetting its contents.

```
┌─────────────────────────────────────────────────────────────┐
│ ✎ ▾  main.py │ notes.md              ◧ ◨ ⬓  ☰ │  ← area header
├──────────┬──────────────────────────┬───────────────────────┤
│ Recent   │                          │ ≡ Outline ⌕ Search ⎇ │  ← right strip tabs
│ notes    │   editor.buffer          ├───────────────────────┤
│ (left    │   (the pane)             │  active region view   │
│  strip)  │                          │                       │
└──────────┴──────────────────────────┴───────────────────────┘
```

## Keyboard model

Two layers, both synthesized by the registry (no per-module boilerplate) and
scoped to the host view's focus:

1. **Universal position keys** — `t` toggles the **left** strip, `n` the
   **right**, `b` the **bottom** (Blender muscle memory), identical across every
   view. Reserved: a declared `key` of `t`/`n`/`b` is dropped with a warning.
2. **Declared pick letters** — each region view's `key` reveals that view in its
   strip (pressing it again while it's the visible one closes the strip). E.g.
   in an editor buffer: `o` Outline, `s` Symbol Search, `g` Provenance.

## Programmatic reveals

`revealRegionView(viewId)` / `toggleRegionView(viewId)`
(`core/layout/controller.ts`) replace the old reveal/toggle companion buses:
they find the host view, open a host pane if none exists (focusing an existing
instance for non-singleton hosts like `editor.buffer`), and flip the strip —
plain store actions, no mounted-shell handshake or buffering. The Game Board
still pops automatically when a match goes live (`game-ws.ts` `revealBoard`).

The agent drives the same thing with `toggle_region` / `set_region_view`; the
REPL with `dash.layout.toggle_region()` / `set_region_view()`.

## Built-in region hosts

| Host view | Regions (key) |
| --- | --- |
| `editor.buffer` (document) | right: Outline `o`, Symbol Search `s`, Provenance `g`; left: Recent notes `r` |
| `games.lobby` (document) | right: Agent Harness `h`, Ladder `l`, Challenges `c`; bottom: Game Board `v` |
| `training.notebook` (document) | right: Metrics `m`, Architecture `a`, Rollout `u`, Manim, Peers; left: Projects `p` |
| `notebook.editor` (document) | left: Notebooks `k` |
| `flow.editor` (document) | left: Flows `f` |
| `network.peers` (tool) | bottom: Peer Chat, Peer Monitor, Lobby, Agent Relay |
| `commons.directory` (widget) | right: Requests, Profile |
| `observability.io` (tool) | bottom: Inspector |

A view being someone's region view doesn't stop it opening standalone (e.g. the
Agent Harness is also a left-dock tool; the Game Board is also a document).

The two notebook hosts above are different documents on different kernels, and
they are titled apart to say so: `notebook.editor` is **Notebook Editor** (the
domain-neutral `.ipynb` editor) and `training.notebook` is **Training Notebook**
(a project's own notebook, on that project's venv). Both were called "Notebook"
once, which made two identical `Open: Notebook` palette rows and an ambiguous
`show` target — `registry.register` now warns on a duplicate pane title.

## Compared to panel groups

The old system kept companion state in unmounted React state (lost on reload),
used three separate open/close mechanisms (reveal bus, toggle bus, bracket-key
handler), and re-implemented tabs/resize/collapse inside a dockview pane.
Regions delete all of that: one store, one controller, persisted, and the
strips render through the same `PaneHost` as everything else (each region view
gets a synthetic instance id `${hostInstance}:${position}:${viewId}`, so e.g.
per-buffer outlines keep distinct agent-context keys).
