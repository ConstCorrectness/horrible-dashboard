# Module: symdex

The **shared symbol/docs embedding index** — one ingestion pipeline whose corpus
feeds two consumers: the roster agents' semantic retrieval (`symbols.*` tools,
preloaded by the [coder and dba agents](agent-chat.mdx#specialized-agents--delegation))
and the [editor](editor.mdx)'s completion layer (doc snippets on suggestions,
with no embedding lookup on the keystroke path).

## The corpus (four kinds)

| kind | id prefix | source | one document per |
| --- | --- | --- | --- |
| `packages` | `pkg:` | installed curated framework packages (`lsp/pyenv.py` `FRAMEWORK_PACKAGES`) in the resolved interpreter's site-packages | public module/class/function/method — `ast.unparse`d signature + first docstring paragraph |
| `stdlib` | `std:` | the resolved interpreter's **standard library** (`extract_stdlib.py`) | same, one `PackageHarvest` per top-level module |
| `schema` | `schema:` | every saved [database](database.mdx) connection via `driver.introspect` | table (qualified name + column list) |
| `docs` | `doc:` | this repo's `docs/**/*.mdx` | chunk (`library/chunking.chunk_text`) |

Package extraction (`backend/modules/symdex/extract_packages.py`) is **static AST
only — packages are never imported** (imports run side effects and are slow);
private modules (`_*`), `tests/`, and vendored trees are skipped, and per-package
file/symbol caps keep even torch-sized dists bounded. The site-packages probe is
the one subprocess, run on a thread (the Windows `--reload` loop can't spawn
asyncio subprocesses — see `lsp/manager.py`). That probe reports **`site.getsitepackages()`
plus the user site-packages**, not just the `sysconfig` prefix scheme — on a
`pip install --user` layout (the Windows default for a non-venv interpreter) the prefix
directory is nearly empty and every installed package would otherwise be invisible.

### `__all__` re-exports

A parse-only harvest can't see two very common cases: symbols implemented in C
(`collections.defaultdict`, `datetime.datetime`) and symbols re-exported from a
submodule (`pandas.DataFrame`, `typing.List`) — which are exactly the names people
import. Both are listed in the module's `__all__`, so `_emit_reexports` takes that list
at its word and emits any name the AST walk didn't already produce. Those rows carry no
signature or docstring, but they carry the right **import module**, which is what makes
completion insert `from collections import defaultdict`. (Packages that build `__all__`
dynamically — `numpy`, `transformers` — still slip through; the curated
[framework-import source](editor.mdx) covers the common ones.)

### The stdlib's two scopes

The stdlib is harvested into **both** projections but at different breadth:

- The **relational** projection (`code_symbols`) covers the *whole* stdlib — it's a
  cheap SQLite prefix scan and editor completion has to be exhaustive.
- The **embedding** projection covers only `STDLIB_EMBED`, a curated set of ~36 modules
  worth spending vectors on for agent retrieval. Embedding every stdlib symbol would be
  tens of thousands of vectors against a local embedder for very little retrieval gain.

## Build cost

A full build is ~46k symbols. Getting that from *hours* down to minutes was mostly
about noticing that the embedder was never the bottleneck — it answers in ~65ms, but
the requests were going out ~2s apart.

| what | before | after |
| --- | --- | --- |
| LanceDB write | one `merge_insert` **per document** (~1.5s) | one per **256-doc chunk** (~6ms/doc) |
| model discovery | one `GET /api/tags` **per document** | once per build (60s TTL cache) |
| HTTP client | a new `AsyncClient` per document | one shared client per batch |
| embed request | one per document | one batched `/api/embed`, or 8-way concurrent |
| documents embedded | all ~40k | only those **with a docstring** (~17k) |

`merge_insert` is the one to internalize: it's a **whole-table** operation, so its cost
tracks table size, not the number of rows you pass it. Handing it one row at a time is
the worst possible use of it — measured at ~1.5s per call on a 5k-row table, which is
16 hours for a 40k-symbol build spent entirely in Arrow.

The docstring filter is a quality decision as much as a speed one: 58% of harvested
symbols have no docstring, and their embeddable text degenerates to the name restated
as a sentence (`"class numpy.linalg.LinAlgError"`). That's no semantic signal — you
find those by prefix, which the relational index already does instantly — and it
dilutes the vector space with near-duplicate rows.

The same chunked shape is used by [`code/semantic.py`](code.mdx), which had the
identical per-document loop.

## Two projections

1. **LanceDB `symdex` collection** (`database/vectorstore.py`) — the semantic
   space, searched by `symbols.searchDocs` / `GET /api/symdex/search`.
2. **`code_symbols` in `app.db`** (`lsp/symbol_store.py`, sources `pkg:<dist>` and
   `std:<module>`, with `doc` and `imp` columns) — the same symbols in the relational
   prefix index, so `GET /editor/complete` returns signature + doc snippet + the
   importable module from the SQLite scan it already does. **Embedding lookups never
   sit on the keystroke path.**

The relational projection is written **even when the embedder is offline**. It needs no
vectors, and editor completion depends on it — gating it behind a live embedding
provider meant intellisense silently stayed empty whenever the local model wasn't up.

## The embed-model drift guard

`get_embedding` picks its model dynamically (whatever embedding model the
provider offers — 384/768/1024 dims) and silently falls back to a 384-dim hash
offline, while a LanceDB collection's vector width is fixed at first write. The
index therefore keeps a meta sidecar (`$HORRIBLE_DATA_DIR/symdex.meta.json`,
`{embed_model, dim, counts}`):

- **Model changed** → the next reindex rebuilds the requested kinds **plus any kind
  that actually had vectors** under the old model. A kind that was never built has
  nothing to invalidate, and rebuilding it here would drag the whole stdlib and every
  installed package into what should be a targeted repair.
- **Only the hash fallback available** → reindex refuses (never poisons a
  real-model collection); search returns `status: "reindex_needed"` with empty
  results — never a `DimensionMismatch` crash.

## Triggers & status

- `POST /api/symdex/reindex` `{kinds: ["packages"|"stdlib"|"schema"|"docs"]}` —
  manual, detached.
- Auto-kick: the first `GET /api/editor/python-env` resolve with an interpreter
  starts a background build of **whichever of `stdlib` / `packages` is still empty**
  (`_kick_symbol_index` in `lsp/routes.py`); creating or editing a database connection
  re-kicks the `schema` kind.

  The kick holds a **strong reference** to its task and logs the outcome.
  `asyncio.create_task` only keeps a weak reference, so the build could be
  garbage-collected mid-flight — and with failures swallowed, the packages corpus
  could sit empty indefinitely with nothing to show why.
- Progress streams on the **`symdex` `/ws` channel**
  (`{event: "index", data: {state, kind, done, total}}`); `GET /api/symdex/status`
  reports `{building, total, counts, embed_model}`.

## Agent tools (group `symbols`)

- `symbols.searchDocs(query, kind?, limit?)` — semantic retrieval across the
  corpus (read-only). The dba agent uses `kind: "schema"` before writing SQL
  against unfamiliar tables; the coder agent uses it before coding against an
  unfamiliar API.
- `symbols.lookup(name, lang?)` — exact prefix lookup via the relational
  projection (fast, offline).

## Backend surface

`backend/modules/symdex/`: `models.py` (Pydantic), `extract_packages.py` /
`extract_schema.py` / `extract_docs.py` (sync extractors, run on threads),
`index.py` (`SymdexIndex` singleton + the `symdex` broadcaster), `routes.py`
(`/api/symdex/*`), `tools.py` (registered from `app.py` like the training/games
tools). Modeled on `code/semantic.py`'s `SemanticIndex`.

## Browser vs desktop

Identical — everything runs in the backend; the frontend only sees `/ws`
progress events and enriched completion items.
